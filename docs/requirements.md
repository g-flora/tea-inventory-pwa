# flora-app 要件整理

## 1. アプリの目的

フローラ社内の業務を一元的に管理し、日々の確認・入力・共有にかかる手間を減らすための社内業務アプリを作る。

現時点では詳細な業務範囲は未確定のため、まずは社内でよく発生する情報管理・進捗確認・履歴確認を扱える小さな業務基盤として検討する。

## 2. 想定ユーザー

- フローラ社内スタッフ
- 業務進捗を確認する管理担当者
- 顧客・案件・作業状況などを日常的に記録する担当者
- 必要に応じて閲覧のみ行う関係者

## 3. 最初に作る機能候補

- ログイン・ユーザー管理
- 案件または業務タスクの一覧表示
- 案件または業務タスクの新規登録・編集
- ステータス管理
- 担当者の設定
- コメント・メモの記録
- 更新履歴の確認
- 簡単な検索・絞り込み

## 4. 後回しにする機能

- 複雑な権限管理
- 外部サービス連携
- 高度な通知機能
- CSV・Excel の高度な入出力
- ダッシュボードや分析グラフ
- スマートフォン専用の最適化
- 自動ワークフロー
- 承認フロー

## 5. 使用候補技術

- フロントエンド: Next.js / React / TypeScript
- UI: Tailwind CSS または既存のコンポーネントライブラリ
- バックエンド: Next.js API Routes または別 API サーバー
- データベース: PostgreSQL
- ORM: Prisma
- 認証: NextAuth.js または Supabase Auth
- ホスティング: Vercel または社内運用環境

## 6. 次に決めること

- 最初に管理したい業務対象
- 主要ユーザーと利用人数
- 必要な入力項目
- ステータスの種類
- 権限の考え方
- 既存データの有無
- 外部連携が必要か
- 運用開始までに必要な最小機能
